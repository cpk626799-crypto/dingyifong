## 部署方式

將本資料夾全部檔案上傳至 GitHub Pages 專案根目錄即可。

若是更新既有 GitHub Pages：

1. 解壓縮本 ZIP。
2. 將資料夾內所有檔案上傳或覆蓋到 GitHub repository。
3. Commit changes。
4. 等待 GitHub Pages 自動部署。

## v2.0 會員制第一階段

- 以 Supabase Auth + `public.profiles` RLS 建立會員登入與權限。
- 公開頁：`login.html`、`register.html`、`verify.html`、`pending.html`。
- 受保護頁：原有全部術數查詢與規則頁；未登入、待審核、停權、未到啟用日或已到期皆不能進入。
- 管理員後台：`admin.html`，可審核會員、切換 active / pending / suspended、設定 free / formal / permanent、啟用日與到期日。
- Supabase 前端設定：`assets/supabase-config.js`；只包含 Project URL 與 Publishable key，不含 Secret / service_role / Database Password。
- Supabase JS 固定使用 `@supabase/supabase-js@2.112.2` ESM CDN。

### 正式測試前仍需完成

1. 部署到 Cloudflare Pages 取得 `https://<project>.pages.dev` 網址。
2. Supabase → Authentication → URL Configuration：
   - Site URL 設為正式 Cloudflare Pages 網址。
   - Redirect URLs 加入 `https://<project>.pages.dev/**`（或至少 `verify.html`）。
3. 再以一般 Email 註冊測試：Email 驗證 → pending → 管理員後台改 active → 登入系統。
4. 正式營運前建議設定 Custom SMTP、隱私權政策、會員使用條款。

## v2.2 會員方案權限

- 一般會員（free）：僅可進入「四大吉時月表」，且只能查看臺灣時間的當月份；其他查詢入口鎖定，直接輸入其他功能網址亦會被導回四大吉時頁。一般會員不開放列印／另存 PDF。
- 正式會員（formal）：可使用全部查詢功能，但不開放各「說明／規則」頁與頁內標記之規則說明區塊。
- 永久會員（permanent）：全部查詢與說明功能皆可使用。
- 管理員（admin）：不受方案限制，全部功能可使用。

方案欄位沿用 Supabase `profiles.plan` 的 `free / formal / permanent`，不需修改資料表結構。
